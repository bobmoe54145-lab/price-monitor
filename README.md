# 楽天 競合価格モニター

楽天市場の商品検索 API で競合ショップの価格・販売状況を取得し、Google スプレッドシートに集計します。
GitHub Actions で 1 日 4 回（JST 8/12/16/20 時）自動実行します。

## しくみ

```
master（監視する商品を入力）
   ↓ 楽天 API で検索 → 型番・除外語で絞り込み
latest    … 最新の出品状況（1 ショップ 1 行）
summary   … 商品ごとの最安値・自社との差額・自社が最安か
history   … 価格や販売状況が変わったときだけ追記（新規/値下げ/値上げ/販売不可/販売再開/未検出/再検出）
trend     … 実行ごとの最安値・中央値の推移（グラフ用）
log       … 実行結果
```

- **在庫数は取得できません。** API で分かるのは「販売可/販売不可」だけです。
- 「実質価格(概算)」は `価格 − 価格×ポイント倍率%` です（倍率 1 = 1%）。SPU 等は含みません。
- 送料は「込/別」の区別のみで、送料別の金額は価格に含まれません。
- 異常値（0 円、前回比 10 倍/10 分の 1）は採用せず、前回の値を維持して log に記録します。

## セットアップ

### 1. 楽天ウェブサービス

1. https://webservice.rakuten.co.jp/ でアプリを登録し、**アプリ ID** と **アクセスキー**を取得します。
2. アプリ種別は **Web アプリケーション**を選び、「許可されたWebサイト」にドメインを 1 つ登録します
   （例: `https://<GitHubユーザー名>.github.io`。実在しなくても構いませんが、登録値と後述の `RAKUTEN_ORIGIN` を一致させます）。
   GitHub Actions は実行ごとに IP が変わるため、IP 固定が必要な「バックエンドサービス」種別は使えません。
3. 仕様は 2026 年に改定されています。最新の必須項目・利用規約を公式ドキュメントで確認してください。

### 2. Google

1. Google Cloud でプロジェクトを作り、**Google Sheets API** を有効化します。
2. サービスアカウントを作成し、JSON キーをダウンロードします（**リポジトリに入れない**）。
3. 空のスプレッドシートを作成し、サービスアカウントのメールアドレスに**編集者**として共有します。

### 3. ローカルで動作確認

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env        # 値を記入（RAKUTEN_ORIGIN は 1 で登録したドメイン）

python -m price_monitor init-sheets                      # シートを作成
python -m price_monitor search "キーワード" --model 型番   # 候補を確認（シートには書かない）
python -m price_monitor run --dry-run                    # 取得と集計だけ（書き込みなし）
python -m price_monitor run                              # 本番実行
pytest                                                   # テスト
```

**最初の `search` で、API の応答が正しく読めているか（件数・価格）を必ず確認してください。**

### 4. master シートの書き方

| 列 | 内容 |
|---|---|
| 管理ID | 重複しない任意の ID |
| 商品名 | 表示用 |
| 検索キーワード | 楽天で検索する語（`search` で試して調整） |
| 型番(必須) | 商品名に含まれるべき語。**スペース区切りで複数指定でき、すべて含むものだけ残す**（語順は不問）。型番がない商品は「サイズ 入数」など（例: `ぐんぐん吸収パンツ Mサイズ 66枚`）。全角/半角・大小文字・ハイフンの違いは吸収。1 文字だけの語（`M` 等）は誤一致しやすいので避ける |
| 除外キーワード | まとめ売り・中古等を除く語（例: `セット まとめ買い 中古 訳あり ケース ×2 ×3 ×4 パック 個入`）。スペースかカンマ区切り。**商品名だけ**を見て判定する（API 側の除外は説明文まで見て単品まで消えるため使わない） |
| 除外ショップ | 自社ショップ等の shopCode |
| 固定itemCode | 指定するとキーワード検索をせず、この商品だけを追跡（`search` で確認した `[shop:1234]`） |
| 価格下限 | これ未満は検索対象外（付属品などの除外に） |
| 自社価格 | 比較用 |
| 監視 | 空欄/ON で監視、OFF で停止（停止中は状態を保持） |

### 5. GitHub Actions で自動実行

1. このフォルダを GitHub の **private** リポジトリとして push します（`.env` と JSON キーは `.gitignore` 済み）。
2. Settings → Secrets and variables → Actions に次を登録します。
   `RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY` / `RAKUTEN_ORIGIN` / `SPREADSHEET_ID` /
   `GOOGLE_SERVICE_ACCOUNT_JSON`（JSON ファイルの中身をそのまま貼る）
3. Actions タブの price-monitor → Run workflow で手動実行して確認します。

補足: 実行が失敗すると GitHub から通知メールが届くのが既定です（不要なら GitHub の通知設定で止められます）。
スケジュール実行は数分〜数十分遅れることがあります。

## 運用の注意

- 検索は**価格の安い順に最大 90 件（3 ページ）**を見ます。関連度順だと、ショップ数の多い商品で結果が実行ごとに入れ替わり、偽の「未検出/再検出」や最安値のぶれが出たためです（実測済み）。
- 商品名だけでは入数や梱包が分からない出品（ケース売りなのに名前に書いていない等）は混ざることがあります。`summary` の最安値・中央値が不自然なときは、`search` で名前を確認し、除外キーワードを足してください。
- **付属品・1 本売りの混入は `価格下限` で防ぎます。** 型番が商品名に入っていても、イヤーピースや 1 本売り等の安い出品が混ざることがあります（実例: WF-1000XM5 の最安 820 円、ポカリスエット 24 本の最安 228 円）。商品の相場の半値程度を下限にしてください。
- **検索キーワードの各語は 2 文字以上**にしてください（楽天 API の仕様。`GO 3` の `3` のような 1 文字の語があると、その商品は取得エラーになります）。
- 似た別商品（例: ポカリスエット と イオンウォーター）は、必須語では区別できないことがあります。除外キーワードで除いてください。
- 同じ商品でも、サイズ・入数が違う出品ページは別商品として扱います。1 つの商品ごとに `master` の行を分けてください。
- 実行時間の目安: 商品 1 件あたり 1〜2 リクエスト（1 秒間隔）。数十件で 1〜2 分。
- 履歴は「変化があった時だけ」追記するので、シートのセル上限（1000 万）には当面達しません。
- 「未検出」は検索結果から消えた出品です。上位 60 件に入らなくなっただけの場合もあるので、頻発するなら型番やキーワードを絞ってください。
